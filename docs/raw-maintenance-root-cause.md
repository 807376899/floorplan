# Raw Maintenance Delete Root Cause

The failing user path is: admin deletes a floor skeleton row in the raw editor, the browser posts `deleteRow` to the raw-maintenance endpoint, the service deletes matching relational `floor_segments` and `spaces`, and then the response path rebuilds the visible dataset.

The previous regression tests stopped after the service call and checked only relational tables. They did not exercise the real response/read path. In production, `sendVisibleDataset` calls `buildVisibleDataset`, and that function still synchronizes visible legacy JSON payloads back into relational tables. Old plan-copy payloads can still contain full `floor_segments` and `spaces`; after a relation-first delete, that stale payload can upsert the deleted skeleton and bound spaces again. The same read-time synchronization also adds heavy write work to login, delete, and refresh operations, which explains the slow UI.

This iteration found a second performance cause in the live database: historical copy synchronization had written full copies of global spaces and use units into `plan_space_overrides` and `plan_lab_overrides`. Admin bootstrap had to project those redundant rows and return roughly 1000 visible spaces even though most were identical to the global baseline. The relation-first read path was correct, but the override tables were still carrying legacy full-copy payloads instead of true per-plan differences.

There was also an independent startup delay: `index.html` loaded SheetJS from an external CDN as a deferred startup script. On a slow or blocked network, the browser could keep the page waiting before the app reached a usable state, even though Excel import/export is optional for ordinary viewing and editing.

The fix keeps visible-dataset reads relation-first once relational rows exist, prunes redundant plan-space and plan-lab overrides with a backup before startup cleanup, and prevents copy saves from writing baseline-identical rows back into override tables. Raw-maintenance deletes also clean matching plan-space overrides, including historical payloads that used `skeleton_code` instead of `segment_code`, so copy-scoped spaces bound to a deleted global skeleton do not remain visible. SheetJS is now loaded only when `.xlsx` import/export is requested; failure to load it leaves the main app usable and falls back to JSON guidance.
